Arrays & Strings

Contiguous, index-addressable sequences — the most common input type in interviews. Strings behave like immutable arrays of characters in most languages, including Python.

Strengths

O(1) random access by index. Cache-friendly contiguous memory. Simple to reason about.

Weaknesses

Insertion/deletion in the middle is O(n) (shifting). Fixed-size in low-level languages; Python lists auto-grow (amortized O(1) append).

In-place reversal is a canonical warm-up. It uses O(1) extra space with two indices converging from the ends.

def reverse_in_place(a):
    i, j = 0, len(a) - 1
    while i < j:
        a[i], a[j] = a[j], a[i]
        i += 1
        j -= 1
    return a

# Strings are immutable in Python, so build a new one:
def reverse_string(s):
    return s[::-1]
Tip When a problem says "sorted array", think binary search or two pointers. When it says "subarray" or "substring", think sliding window or prefix sums.

Prefix sums

Precomputing cumulative sums turns repeated range-sum queries from O(n) each into O(1) each.

def build_prefix(nums):
    prefix = [0] * (len(nums) + 1)
    for i, x in enumerate(nums):
        prefix[i + 1] = prefix[i] + x
    return prefix

def range_sum(prefix, lo, hi):   # inclusive [lo, hi]
    return prefix[hi + 1] - prefix[lo]

Hash Maps & Sets

A hash map (dict) stores key→value pairs with average O(1) lookup, insert, and delete. It hashes the key to a bucket index; collisions are resolved by chaining or open addressing. A set is the same structure storing only keys.

Fig 3. A hash table: keys hash to bucket indices; collisions chain within a bucket.
OperationAverageWorst
Insert / lookup / deleteO(1)O(n) (all keys collide)

# Classic: two-sum in one pass with a hash map
def two_sum(nums, target):
    seen = {}                      # value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []

# Set for O(1) membership / de-duplication
unique = set([1, 2, 2, 3])         # {1, 2, 3}
Watch out Keys must be hashable (immutable). Lists and dicts can't be keys; use tuples or frozensets instead.

Stacks & Queues

A stack is LIFO (last-in, first-out) — think a stack of plates. A queue is FIFO (first-in, first-out) — think a line at a counter. Both support O(1) push and pop at their respective ends.

Stack uses

Undo history, matching brackets, DFS, expression evaluation, backtracking, call stacks.

Queue uses

BFS, task scheduling, buffering, producer/consumer pipelines, rate limiting.
from collections import deque

stack = []
stack.append(1)       # push
stack.append(2)
top = stack.pop()     # 2  (LIFO)

queue = deque()
queue.append(1)       # enqueue
queue.append(2)
front = queue.popleft()  # 1  (FIFO)

# Valid parentheses with a stack
def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for c in s:
        if c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False
        else:
            stack.append(c)
    return not stack
Tip Use collections.deque for queues, not a plain list — list.pop(0) is O(n), while deque.popleft() is O(1).

Linked Lists

A sequence of nodes where each node holds a value and a pointer to the next node. Unlike arrays, there is no random access, but insertion/deletion at a known node is O(1) because no shifting is required.

OperationArrayLinked list
Access by indexO(1)O(n)
Insert/delete at headO(n)O(1)
Insert/delete at known nodeO(n)O(1)
SearchO(n)O(n)
class ListNode:
    def __init__(self, val=0, nxt=None):
        self.val = val
        self.next = nxt

# Iterative reversal: the single most-asked linked-list question
def reverse_list(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next     # save next
        cur.next = prev    # flip pointer
        prev = cur         # advance prev
        cur = nxt          # advance cur
    return prev            # new head
Two-pointer tricks Use slow/fast pointers to find the middle (fast moves 2x) or to detect a cycle (Floyd's tortoise and hare — they meet iff a cycle exists). Use a dummy head node to simplify edge cases when the head itself might change.
