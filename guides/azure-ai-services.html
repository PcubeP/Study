Azure AI Services — Overview & Taxonomy

Azure AI Services is Microsoft's unified portfolio of production-ready AI APIs, formerly known as Azure Cognitive Services. Since 2023 the umbrella explicitly includes Azure OpenAI Service, Azure AI Search, and Azure AI Foundry alongside the classic Vision, Language, Speech, Document Intelligence, and Content Safety workloads — all accessed through a single Azure resource type: Microsoft.CognitiveServices/accounts.

Azure OpenAI Service — Models & Deployments

Azure OpenAI Service is the enterprise-grade access layer for OpenAI's models. Rather than calling api.openai.com directly, you call your own Azure-hosted endpoint with your data remaining in your tenant. You provision deployments — named instances of a specific model version — and call them by deployment name, not model ID.

PTU vs Standard Provisioned Throughput Units (PTU) give deterministic, low-latency responses because capacity is reserved for you. Break-even vs Standard typically occurs around 60–70 % sustained utilization. Below that, Standard is cheaper.
What is the difference between a model name and a deployment name in Azure OpenAI?
The model name (e.g., gpt-4o) identifies the AI architecture and version in the catalog. The deployment name is a custom label you assign when you create a deployment in your resource (e.g., my-gpt4o-prod). In API calls you always reference the deployment name in the model field — Azure resolves it to the underlying model. This lets you swap model versions by redeploying without changing application code.
When should you choose Provisioned Managed (PTU) over Standard deployment?
Choose PTU when you need guaranteed, predictable latency and your workload has steady, high throughput (typically above 60–70% sustained utilization). Standard is better for variable or bursty traffic because you only pay for what you use. PTU requires an upfront capacity reservation (billed per hour per PTU) so it is cost-effective only when utilization is consistently high.

Chat Completions, Embeddings & Streaming API

Azure OpenAI exposes the same Chat Completions, Completions, Embeddings, and Images APIs as OpenAI — with the addition of an azure_endpoint and an api_version query parameter. The openai Python SDK v1.x supports Azure natively via AzureOpenAI.

Chat Completions — Core Structure

PYTHON
from openai import AzureOpenAI
import os

client = AzureOpenAI(
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),   # https://myaoai.openai.azure.com/
    api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    api_version="2025-04-01-preview"
)

response = client.chat.completions.create(
    model="gpt-4o",           # deployment name, NOT model family name
    messages=[
        {"role": "system", "content": "You are a concise technical assistant."},
        {"role": "user",   "content": "Explain RAG in two sentences."}
    ],
    temperature=0.3,
    max_tokens=512,
    top_p=1.0,
    frequency_penalty=0.0,
    presence_penalty=0.0
)
print(response.choices[0].message.content)
print("Tokens used:", response.usage.total_tokens)

System prompt discipline For production use, always include a system prompt that (a) defines the model's persona and constraints, (b) instructs it to cite sources if using RAG, and (c) tells it to respond with "I don't know" rather than hallucinating when context is missing.

Function Calling / Tool Use

Pass a tools list of JSON Schema-described functions. The model returns a tool_calls array with name + arguments when it decides to call a tool. Your code executes the function and appends the result as a tool role message, then calls the API again to get the final answer.

How does token counting work in Azure OpenAI, and why does it matter for cost?
Every API call is billed on input tokens + output tokens. Input tokens include the system prompt, all previous turns in the conversation, and any tool definitions — so long conversations and large system prompts accumulate cost rapidly. Use tiktoken to count tokens before sending. For GPT-4o, 1 image counts as a fixed number of tokens depending on resolution (auto-detail uses ~85 base + 170 per 512-px tile). Minimise cost by: (1) summarising conversation history, (2) trimming tool schemas, (3) caching static system prompts with Azure's prompt-caching feature where available.

Azure AI Vision & Computer Vision

Azure AI Vision (Image Analysis 4.0) unifies optical character recognition, object detection, image captioning, smart cropping, and background removal into a single modern API. Custom Vision adds trainable classification and object detection.

Image Analysis 4.0 Features

Caption / Dense Captions: natural-language description per image or per bounding box.

Object Detection: bounding boxes + labels for 10,000+ concepts.

OCR / Read: layout-aware text extraction from images and PDFs; returns word, line, and paragraph bounding polygons.

Smart Crops: generates crop coordinates respecting visual saliency for any target aspect ratio.

Background Removal: segmentation mask returning foreground or background as PNG.

Custom Vision & Face

Custom Vision (classification): image multi-class and multi-label classifiers trained on as few as 15 images per class.

Custom Vision (detection): object detection with labelled bounding boxes.

Face API (Limited Access): face detection, liveness, verification, and grouping. Requires approval; identification and emotion features restricted per RAI policy.

Spatial Analysis: people-counting and zone analytics for on-premises IoT Edge deployments.

Azure AI Language Services

Azure AI Language consolidates a broad suite of NLP capabilities — sentiment analysis, NER, key phrase extraction, summarisation, conversational understanding, custom text classification, and question answering — under one unified SDK and resource.

Available Capabilities

Sentiment & Opinion Mining

Document-level and sentence-level sentiment (positive / neutral / negative) with aspect-opinion pairs. Supports 120+ languages.

Named Entity Recognition

Identifies persons, locations, organisations, dates, phone numbers, URLs, IP addresses, and domain-specific entities (healthcare, finance) out of the box.

PII Detection & Redaction

Detects and optionally masks email addresses, SSN, credit card numbers, phone numbers, and healthcare entities in text and documents.

Summarisation

Extractive (selects representative sentences) and abstractive (generates a new summary). Conversation summarisation available for call centre transcripts.

CLU (Conversational Language Understanding)

Replacement for LUIS. Train intent classification and entity extraction models on your own utterances. Integrates with Bot Framework and Copilot Studio.

Custom Question Answering

Replacement for QnA Maker. Build FAQ knowledge bases from documents, URLs, or manual Q&A pairs; returns ranked answers with confidence scores.

Azure AI Speech Services

Azure AI Speech provides enterprise-grade speech recognition, synthesis, translation, and speaker recognition, with support for custom acoustic and language models tailored to domain-specific vocabulary.

Speech-to-Text (STT)

Real-time: streaming recognition from microphone or audio stream with word-level timestamps and confidence scores.

Batch: asynchronous transcription of audio files in blob storage; returns JSON with detailed timestamps.

Fast Transcription: low-latency file transcription (faster than real-time batch) for short audio.

Whisper on Azure: OpenAI Whisper model available as an Azure OpenAI deployment for multilingual transcription.

Text-to-Speech (TTS)

Neural voices: 500+ prebuilt neural voices across 140+ locales. SSML supported for pitch, rate, emphasis, and pauses.

Custom Neural Voice: fine-tune a voice from your own recorded speech samples (requires Microsoft approval).

Speech Translation: real-time speech-to-speech or speech-to-text translation across 100+ language pairs.

Speaker Recognition: speaker verification (is this the same person?) and speaker identification (who is speaking?).

Custom Speech — when and how

Custom Speech lets you adapt a base speech recognition model to improve accuracy for:

  • Domain-specific jargon (medical, legal, financial terminology)
  • Unusual proper nouns (product names, brand names, people's names)
  • Noisy or acoustic environments different from training data

Process: upload audio + transcripts to a Speech resource → create a Custom Speech project → train a custom endpoint → test WER (word error rate) → deploy and reference in your SpeechConfig via endpoint_id. Audio data requirements: minimum ~1 hour for noticeable improvement, 10–20 hours for significant gains.

Azure AI Search — Vector & Hybrid Search

Azure AI Search is a fully managed enterprise search service that combines BM25 keyword retrieval, approximate nearest-neighbour (ANN) vector search, and a neural semantic ranker into a unified hybrid pipeline. It is the retrieval backbone for most enterprise RAG architectures on Azure.

Figure 3 — Azure AI Search hybrid retrieval pipeline. BM25 and vector search run in parallel; scores are merged by Reciprocal Rank Fusion (RRF); the optional semantic ranker applies a cross-encoder for final re-ranking.

Python: Hybrid Search Query

PYTHON
from azure.search.documents import SearchClient
from azure.search.documents.models import VectorizedQuery
from azure.core.credentials import AzureKeyCredential
import os

search_client = SearchClient(
    endpoint=os.getenv("SEARCH_ENDPOINT"),
    index_name="documents",
    credential=AzureKeyCredential(os.getenv("SEARCH_ADMIN_KEY"))
)

def hybrid_search(user_query: str, query_vector: list, top: int = 5):
    vector_query = VectorizedQuery(
        vector=query_vector,
        k_nearest_neighbors=50,    # retrieve 50 vector candidates, then fuse
        fields="content_vector"
    )
    results = search_client.search(
        search_text=user_query,           # BM25 keyword leg
        vector_queries=[vector_query],    # vector leg
        select=["id", "title", "content"],
        query_type="semantic",            # enable semantic ranker
        semantic_configuration_name="my-semantic-config",
        top=top
    )
    return [dict(r) for r in results]
Semantic ranker The semantic ranker is a cross-encoder that re-reads the query against each candidate passage. It adds ~100–200 ms latency but significantly improves relevance for question-like queries. It is billed separately (per 1,000 semantic queries). Available on Basic tier and above.
What is Reciprocal Rank Fusion (RRF) and why does Azure AI Search use it for hybrid retrieval?
RRF is a score-merging algorithm: it ranks documents by the sum of 1 / (k + rank) across each retrieval leg, where k (typically 60) dampens the effect of early rankings. Because it uses rank positions rather than raw scores, it correctly merges BM25 scores (whose scale depends on term frequencies) with cosine-similarity vector scores (bounded 0–1) without rescaling. The result is that a document appearing in the top ranks of both legs is pushed to the top of the fused result, regardless of absolute score values.

RAG Pattern End-to-End

Retrieval-Augmented Generation (RAG) grounds an LLM's answers in a private knowledge corpus, eliminating hallucinations about proprietary data. The canonical Azure RAG stack is: Azure Blob / SharePoint → Document Intelligence → Azure AI Search (hybrid) → Azure OpenAI (GPT-4o).

Two-Phase Architecture

Source Docs -> Chunk & Enrich -> Embed (text-embedding-3-large) -> AI Search Index (vector + BM25)
User Query -> Embed Query -> Hybrid Retrieval -> Augment Prompt -> Azure OpenAI (GPT-4o) -> Grounded Answer

Complete RAG Function

PYTHON
from openai import AzureOpenAI
from azure.search.documents import SearchClient
from azure.search.documents.models import VectorizedQuery
from azure.core.credentials import AzureKeyCredential
import os

aoai = AzureOpenAI(
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    api_version="2025-04-01-preview"
)
search = SearchClient(
    os.getenv("SEARCH_ENDPOINT"), "documents",
    AzureKeyCredential(os.getenv("SEARCH_ADMIN_KEY"))
)

def get_embedding(text: str) -> list:
    return aoai.embeddings.create(
        model="text-embedding-3-large", input=text
    ).data[0].embedding

def answer_with_rag(question: str) -> str:
    # 1. Embed the question
    q_vec = get_embedding(question)

    # 2. Hybrid retrieval
    vq = VectorizedQuery(vector=q_vec, k_nearest_neighbors=30, fields="content_vector")
    hits = search.search(
        search_text=question,
        vector_queries=[vq],
        select=["title", "content"],
        top=4
    )
    context = "\n\n".join(
        f"[Source: {h['title']}]\n{h['content']}" for h in hits
    )

    # 3. Augmented generation
    resp = aoai.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system",
             "content": (
                 "Answer ONLY from the context below. "
                 "Cite sources as [Source: title]. "
                 "If the answer is not in the context, say 'I don't know'.\n\n"
                 + context
             )},
            {"role": "user", "content": question}
        ],
        temperature=0.0,
        max_tokens=800
    )
    return resp.choices[0].message.content

What is the difference between semantic ranking and vector search in Azure AI Search?
Vector search finds documents whose stored embeddings are geometrically close (high cosine similarity) to the query embedding. It captures semantic meaning but requires documents to have been pre-embedded and indexed in vector fields. Semantic ranking is a separate, post-retrieval step: it uses a cross-encoder transformer to re-read the query against each candidate passage and re-rank them by passage relevance. Semantic ranking can be applied to the output of keyword, vector, or hybrid search — it does not require vector fields. The two are complementary: vector search provides good candidate recall; semantic ranking improves precision of the final top-K.
How do you prevent a RAG system from returning outdated information after documents are updated?
Use incremental indexing via an AI Search Indexer with a dataChangeDetectionPolicy (e.g., SQL HighWaterMark or Blob Storage last-modified timestamp). The indexer re-crawls only changed or new documents and updates/deletes the corresponding index entries. For near-real-time needs, call the index REST API or SDK directly from your document management pipeline (push model). Always store a last_updated metadata field in the index so you can filter with $filter=last_updated ge 2025-01-01T00:00:00Z or display freshness to users.

Azure AI Foundry & ML Studio

Azure AI Foundry (released 2024, unifying Azure Machine Learning Studio and Azure AI Studio) is the end-to-end platform for building, evaluating, and deploying AI applications and models on Azure. It introduces a Hub → Project organisational model shared by all team members.

Hub & Project Model

A Hub is the top-level Azure resource that holds shared infrastructure: compute, storage, connections to services (Azure OpenAI, AI Search, Application Insights), and network/identity configuration.

A Project lives inside a Hub and isolates a single application or team workstream. Projects share the Hub's connections and compute but have separate experiment tracking, deployments, and file stores.

Model Catalog

Browse and deploy 1,600+ models: Azure OpenAI models, Meta Llama 3/4, Mistral Large, Phi-4, Cohere Command R+, Falcon, and many more via serverless API deployments (pay-per-token, no GPU provisioning) or managed online endpoints (dedicated VMSS).

Each model card includes benchmark scores (MMLU, HumanEval, MT-Bench) and pricing to aid model selection.

Prompt Flow

A visual DAG-based orchestration framework. Nodes can be: LLM (call any deployed model), Prompt (Jinja2 template), Python (arbitrary code), Embedding, and Vector DB lookup. Flows are versioned, testable with batch inputs, and deployable to managed endpoints.

Evaluations

Built-in metrics: Groundedness (is the answer supported by context?), Relevance (does it answer the question?), Coherence, Fluency, and Similarity. All use GPT-4 as an LLM judge. Results feed an experiment tracker for A/B comparison of prompt variants and model choices. Custom evaluators (Python functions) are also supported.

Azure ML Studio vs AI Foundry — what moved where

Azure AI Foundry absorbed Azure AI Studio (formerly the AI Studio preview) and added tighter integration with Azure Machine Learning. Key movements:

  • Model fine-tuning jobs, compute clusters, and MLflow experiment tracking remain in the ML Studio / AI Foundry unified portal.
  • Prompt Flow migrated from ML Studio into AI Foundry Projects.
  • Responsible AI dashboard (fairness, error analysis, model explanations) is in the ML Studio / Foundry model evaluation section.
  • Managed Online Endpoints deploy both traditional ML models and LLM-based flows.

For new projects, use AI Foundry as the entry point. Azure ML Python SDK v2 (azure-ai-ml) manages compute and pipelines; AI Foundry SDK (azure-ai-projects) manages connections, deployments and evaluations.

Responsible AI & Content Safety

Microsoft's Responsible AI Standard applies to all Azure AI Services. Azure OpenAI additionally implements runtime content filters that inspect every request and response — and these filters are mandatory; they cannot be disabled unless Microsoft grants an exception via the Limited Access program.

Microsoft's Six Responsible AI Principles

Fairness

AI systems should treat all people equitably and not produce discriminatory outcomes based on race, gender, age, disability, nationality, religion, or other protected characteristics.

Reliability & Safety

Systems should perform as designed, handle failures gracefully, and not cause unintended harm. This includes testing under adversarial conditions and setting safe fallback behaviors.

Privacy & Security

Data used to interact with AI must be protected. Azure AI Services do not use customer prompts or data to retrain models. Encryption at rest and in transit is enforced.

Inclusiveness

AI should empower people of all abilities and backgrounds. Speech services support diverse accents; Vision APIs are tested across skin tones; Language APIs cover 100+ languages.

Transparency

Users and operators should understand what AI systems can and cannot do. Model cards, system cards, and capability documentation accompany all Azure OpenAI model releases.

Accountability

People must be accountable for AI systems they create and deploy. Azure provides audit logs, access reviews, and a human oversight framework (HITL) recommendation for high-stakes scenarios.

Can Azure OpenAI content filters be turned off for a production application?
No, not by default. Content filters run on every request and response and cannot be disabled. If a business scenario legitimately requires different thresholds (e.g., a medical platform discussing self-harm with patients), you can submit a modified content filter configuration request to Microsoft. Approval is case-by-case, time-limited, and still subject to the usage policies. Even with an approved custom configuration you cannot fully disable all filters — you can only relax specific severity thresholds for specific harm categories in specific deployment contexts.

Key rotation Every Azure AI Services resource has two API keys. Rotate without downtime by: (1) updating your app to the secondary key, (2) regenerating the primary key in the portal, (3) updating your app back to the regenerated primary. Automate this with Azure Key Vault + Event Grid-triggered Functions. With Managed Identity you skip this entirely.
What is the difference between Cognitive Services User and Cognitive Services OpenAI User RBAC roles?
Cognitive Services User grants access to all Azure AI Services APIs under a resource — Vision, Language, Speech, Document Intelligence, and Azure OpenAI. Cognitive Services OpenAI User is scoped specifically to the Azure OpenAI API surface and cannot call non-OpenAI services. Use the OpenAI-scoped role to follow the principle of least privilege when a workload only needs to call GPT/embedding endpoints. Neither role allows listing API keys (that requires Contributor) — both rely on Entra ID token auth when used for production least-privilege access.

Async Pattern

PYTHON
import asyncio
from openai import AsyncAzureOpenAI

async def ask(question: str) -> str:
    async with AsyncAzureOpenAI(
        azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
        api_key=os.getenv("AZURE_OPENAI_API_KEY"),
        api_version="2025-04-01-preview"
    ) as client:
        resp = await client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": question}]
        )
        return resp.choices[0].message.content

# Fan-out multiple questions concurrently
questions = ["What is HNSW?", "What is RRF?", "What is PTU?"]
answers = asyncio.run(asyncio.gather(*[ask(q) for q in questions]))
Retry policy All azure-* SDK clients include automatic retry with exponential back-off for transient HTTP 429 (rate limit) and 5xx errors. Tune with RetryPolicy(total=5, backoff_factor=0.8) passed to the client's retry_policy constructor argument. For Azure OpenAI, the openai SDK raises RateLimitError — wrap calls in a tenacity retry decorator for production resilience.
How do you securely provide Azure credentials to a Python application running in Azure App Service?
Enable the System-Assigned Managed Identity on the App Service in the Azure Portal (Identity → Status: On). Then grant that identity the appropriate RBAC role on each target resource (e.g., Cognitive Services OpenAI User on the Azure OpenAI resource). In code, use DefaultAzureCredential() — it automatically uses the Managed Identity token when running in Azure. Locally, the same code falls through to Azure CLI credentials (az login). This pattern requires zero secrets in environment variables, no key rotation, and works transparently across environments.

When to choose Azure OpenAI Choose Azure OpenAI if your organisation: (1) has strict data sovereignty or compliance requirements, (2) already uses Azure and wants unified billing/RBAC, (3) needs VNet/Private Link integration, or (4) is subject to regulated industry requirements (HIPAA, FedRAMP). For a personal side project or early-stage startup without compliance requirements, the direct OpenAI API is simpler and gives faster access to new models.
You are getting HTTP 429 errors from Azure OpenAI. What are your options?
A 429 means you hit a quota limit (TPM or RPM). Options in order of effort: (1) Retry with exponential back-off — transient spikes often resolve themselves; the SDK does this automatically. (2) Reduce request rate — add throttling logic or a queue in front of the API. (3) Request a quota increase in the Azure Portal (takes 3–5 days). (4) Use multiple deployments / regions — distribute load across deployments in different regions, each with its own quota. (5) Switch to Provisioned Managed (PTU) — PTU deployments do not have TPM rate limits; their throughput is reserved. (6) Use the Batch API for non-time-sensitive workloads — async with 50 % price reduction and no TPM limit.
How does Azure OpenAI handle data privacy differently from the direct OpenAI API?
With Azure OpenAI, Microsoft contractually guarantees that: (a) your prompts, completions, and fine-tuning data are not used to train or improve OpenAI's or Microsoft's models, (b) data stays within your Azure region (with Global Standard routing as the exception — disabling it keeps data in-region), and (c) the service is subject to your Azure DPA (Data Processing Agreement). Access to data in motion and at rest requires your tenant's keys. The direct OpenAI API also does not train on API data by default, but it lacks the enterprise legal guarantees, VNet isolation, and Azure compliance certifications. For regulated workloads, Azure OpenAI is the required choice.

Best Practices & Interview Cheat Sheet

A consolidated reference of key patterns, pitfalls, and metrics for production deployments and technical interviews.

Production checklist Use Managed Identity instead of API keys in all Azure-hosted workloads. Store any keys that must be used in Azure Key Vault with automatic rotation. Enable diagnostic logging on all AI resources and route to Log Analytics. Set up alerts on HTTP 429 rate, latency P99, and token consumption per deployment. For Azure OpenAI, configure a custom content filter policy and review Content Safety block logs weekly.
Common pitfalls (1) Calling the model by its catalog name instead of the deployment name — always use the deployment name in the model field. (2) Ignoring system prompt token cost — a 2,000-token system prompt is included in every request. (3) Not validating chunks before embedding — empty or near-empty chunks produce noisy embeddings that pollute retrieval. (4) Using the wrong API version — Azure OpenAI feature availability varies by api_version; always pin to a stable version in production. (5) Not handling semantic ranker availability — it requires Basic+ tier; code should degrade gracefully.
